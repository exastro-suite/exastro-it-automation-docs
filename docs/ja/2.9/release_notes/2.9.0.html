Exastro IT Automation 2.9.0¶

機能追加¶

IaC（Infrastructure as Code）開発支援機能（Exastro AI Assistant）（#2579）¶

Playbook素材集編集画面から生成AIを利用できるようになりました。
AIアシスタントとの対話を通じて、Ansible PlaybookなどのIaCコード作成を支援します。自然言語による問い合わせやコードを含めた相談が可能となり、IaC開発の効率化を支援します。

Ansible Automation Platform連携機能の処理の大幅な見直し（AAP on AWS対応）（#3029）¶

Ansible Automation Platform（AAP）との連携ロジックを全面的に見直し、特にSaaSサービス上で動作するAAPとの連携を最適化しました。これにより、Exastro IT Automation（ITA）固有の資材連携処理において、ITAからAAP（コントロールノードや実行ノード）へのSSH接続が不要となり、実行ノードからITAへのアウトバウンド通信のみで資材連携が可能になります。また、エラーハンドリングやリトライ処理の改善により、連携の信頼性も向上しました。

改善¶

ファイルストレージへの読み書き時のリトライ機能のチューニング対応（#3070）¶

ファイルストレージに対するデータの読み書き処理において、ネットワークの一時的な不安定さやストレージの高負荷などの理由で処理が失敗した場合に自動的に再試行する機能について、リトライ回数や待機時間をユーザが変更できるようにしました。これらのパラメータを環境や運用要件に応じて柔軟に調整できるようになったため、システムの可用性と安定性が向上しました。

Ansible作業実行時の子プロセスの自動復旧機能（AAP連携）（#3032）¶

Ansible Automation Platform（AAP）と連携して作業を実行する際、何らかの理由でAnsible実行コンテナの子プロセスが異常終了した場合に、自動的に子プロセスを再起動する機能を実装しました。これにより、作業実行中に予期しないエラーが発生しても、作業を継続できるケースが増え、運用の自動化レベルが向上しました。特に長時間実行される大規模なインフラ構成作業において、途中で作業が中断されるリスクを最小限に抑えることができます。

Ansible実行エージェントのセットアップスクリプトのコマンドライン引数対応（#3012）¶

Ansible実行エージェントのインストールおよび設定を行うsetup.shスクリプトにおいて、コマンドライン引数を通じて各種パラメータを指定できるようになりました。
この機能により、対話的な入力を行わずに自動化されたスクリプトや構成管理ツールからエージェントのセットアップを実行できるようになり、大規模な環境での展開作業や継続的インテグレーション・デリバリー（CI/CD）パイプラインへの組み込みが容易になりました。

メニューへのデータ操作時の処理速度の大幅な向上（#3022）¶

各種メニュー画面でのデータ操作（閲覧・登録・更新・削除）において、内部的な不要データ検索処理を廃止しました。これにより、特に大量のデータを扱う環境における処理速度が向上しました。

Ansible実行エージェントにおける不要なファイル読み込みの削減（#2999）¶

Ansible実行エージェントが子プロセスを監視する際、不要なファイルの読み込みを行っており、不要な処理の中断を招く可能性を抱えていた問題に対処しました。

Conductor作業における収集機能の結果の確認しやすさの向上（#2746）¶

Conductor作業実行時、パラメータ収集機能の結果を作業状態確認画面に表示するようにしました。収集された内容や、収集処理が成功したか失敗したかの情報を、画面上で確認しやすくなりました。

バックヤードコンテナのメンテナンスモードチェック間隔の最適化（#3037）¶

バックグラウンドで動作する各種処理を担当するバックヤードコンテナにおいて、システムがメンテナンスモードに入っているかどうかを確認する間隔が不適切に設定されており、公開している仕様と実際の仕様に乖離があるため、仕様通りに修正しました。また、メンテナンスモードの状態チェックAPIへの問い合わせもキャッシュを持たせることにより、不必要なアクセスを減らすことができました。

Ansible実行エージェントのPython依存関係の固定（#2957）¶

Ansible実行エージェントで使用するPythonバージョンを動作確認済みの3.11系に固定し、安定した動作を維持できるようにしました。

Ansible実行エージェント有償版コンポーネントのバージョン固定（#3028）¶

Ansible実行エージェントのインストールスクリプトにおいて、有償版コンポーネント（ansible-builder、ansible-runner）を動作確認済みの特定バージョンに固定しました。
これにより、予期しないバージョンアップによる互換性問題を回避できるようになりました。

依存ライブラリの最適化（#3048, #3060）¶

システムで使用している依存ライブラリについて、セキュリティや性能の関連から見直しを行い、修正しました。

バグ修正¶

OASE機能における重複排除およびイベント検索のエラー修正（#2961, #2988, #3051）¶

OASE（Operation Autonomy Support Engine）機能において、複数の不具合を修正しました。まず、OASE Receiverに複数のイベントリクエストが同時に到着した際、重複排除処理が正常に機能せず、同一のイベントが重複して登録される問題を解決しました。次に、イベント履歴画面で特定の組み合わせの検索条件を指定した場合にシステムエラーが発生する問題を修正し、すべての検索パターンで安定して動作するようになりました。さらに、OASE管理画面のイベント収集設定をExcelファイルで一括更新する際、存在しないイベント収集設定IDを指定した場合にIndexErrorが発生する問題を修正し、適切なエラーメッセージを表示するようにしました。これらの修正により、OASEを利用したイベント管理がより安定して運用できるようになりました。

Ansible Automation Platform 2.5での緊急停止機能の不具合修正（#3040）¶

Ansible Automation Platform（AAP）バージョン2.5と連携して作業を実行する際、緊急停止ボタンを押しても作業が停止しない不具合を修正しました。この問題は、AAP 2.5のAPI仕様変更に適切に対応できていなかったことが原因でした。

バージョン差分があるデータのインポート時のエラー修正（#3063）¶

バージョンアップを伴うエクスポート・インポートを実施した際、特定の条件においてエラーが発生し、インポートが失敗する問題を修正しました。

ファイルアップロード時のバリデーションが正しく機能しない不具合の修正（#2766）¶

ファイルをアップロードする際、ファイルのバリデーションチェック（拡張子・サイズ・実体の有無など）が正しく実行されない不具合を修正しました。

Conductor編集機能における複数のUI不具合の修正（#3017, #3016）¶

Conductor（作業フローの定義・実行機能）の編集画面において、複数のユーザーインターフェース（UI）関連の不具合を修正しました。まず、Conductor Callノードで呼び出し先のConductorを選択解除（クリア）した状態で更新ボタンを押せてしまう問題を解決しました。次に、オペレーション個別選択や呼び出しConductorのモーダルダイアログを開いた際、前回選択した内容が残ったままになっている問題を修正しました。

Conductor定期作業実行編集時の表示不具合の修正（#2871）¶

Conductor定期作業実行の編集時に、元々設定されていた値が画面に正しく再表示されない箇所があった問題を修正しました。

ユーザーインターフェース全般における操作性の不具合修正（#3030, #3031, #3050, #3069, #3067）¶

システム全体のユーザーインターフェースにおいて、複数の操作性に関する不具合を修正しました。パスワード入力欄でテキストを選択できない問題、Conductor定義画面のMovement説明欄の高さが適切に調整されない問題、拡張子のないファイルが表示されない問題、ファイル選択ダイアログでファイルを選択しても反応しない問題、そしてレコード編集時に廃止レコードを復活させた後に特定の操作を行うと編集不可項目が編集可能になってしまう問題など、ユーザーの操作体験を損なう様々な問題を修正しました。

Terraform連携機能における変数刈り取り処理の修正（#3010）¶

Terraform連携機能において、HCL（HashiCorp Configuration Language）パーサーライブラリ（python-hcl2）の特定バージョンで変数刈り取り処理が正常に動作しない問題を修正しました。
パーサーライブラリのバージョンを固定し、変数の解析処理が確実に動作するようになりました。

Terraform機能における複雑な変数型のサポート修正（#3044, #3045）¶

Terraform連携機能において、複雑な変数型を使用した場合に作業実行がエラーになる問題を修正しました。
具体的には、tuple型やobject型がネストしている変数、およびobject型の中にlist型のフィールドが含まれる変数を使用した際に、変数の解析や変換処理が正常に行われず、作業実行が失敗する問題がありました。Terraformの型システムを正確に解釈し、複雑なデータ構造を適切に処理できるように修正しました。
